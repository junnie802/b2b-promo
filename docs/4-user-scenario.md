## 문서 목적

`3-prd.md`의 기능 요구사항(FR-1~4), 비즈니스 규칙(BR-1~4), 예외 케이스(EX-1~5)를 바탕으로 관리자/거래처 담당자의 핵심 기능 사용 흐름을 정리한다. 페르소나 배경 스토리는 생략하고 기능 흐름 위주로 작성한다(교육용 MVP).

## 시나리오 1. 거래처 담당자 회원가입

**액터**: 거래처 담당자

**사전조건**: 없음 (비로그인 상태)

**기본 흐름**
1. 회원가입 페이지에서 이메일, 비밀번호, 이름, 소속 거래처 등 정보를 입력한다 (FR-1.1)
2. 가입 요청을 제출한다
3. 서버는 이메일 중복 여부를 확인하고, 중복이 없으면 계정을 생성한다 (FR-1.1)
4. 가입 완료 후 로그인 페이지로 이동한다

**예외/대안 흐름**
- **EX-5 이메일 중복**: 이미 등록된 이메일로 가입 시도 시 서버가 거부하고, 중복 이메일임을 안내한다. 사용자는 다른 이메일로 재입력하거나 로그인 페이지로 이동한다 (FR-1.1, EX-5)

---

## 시나리오 2. 로그인 / 로그아웃

**액터**: 관리자, 거래처 담당자

**사전조건**: 계정 보유 (관리자는 DB 시드로 생성됨, FR-1.0)

**기본 흐름**
1. 로그인 페이지에서 이메일/비밀번호를 입력한다
2. 서버는 인증에 성공하면 access token과 refresh token을 발급한다 (FR-1.2)
3. 사용자는 역할(관리자/거래처 담당자)에 맞는 메인 화면으로 이동한다
4. 사용자는 로그아웃을 요청하면 서버가 refresh token을 무효화하고 로그인 페이지로 이동한다 (FR-1.5)

**예외/대안 흐름**
- **EX-4 비로그인 접근**: 로그인하지 않은 사용자(유효한 access token 없음)가 보호된 기능(프로모션 목록, 마이페이지 등)에 접근하면 로그인 페이지로 리다이렉트한다 (FR-1.3, EX-4)
- **access token 만료**: access token 만료 시 refresh token으로 재발급받아 이용을 계속한다. refresh token도 만료/무효화된 경우 재로그인이 필요하다 (FR-1.4)

---

## 시나리오 3. 관리자 프로모션 등록~게시

**액터**: 관리자

**사전조건**: 관리자 계정으로 로그인 완료

**기본 흐름**
1. 프로모션 등록 화면에서 유형(가격할인/사은품 증정/신제품 시식), 제목, 설명, 기간(시작일/종료일)을 입력한다 (FR-2.1)
2. 게임 적용 여부를 선택한다
3. (게임 미적용) 등록을 제출하면 상태 "예정"으로 프로모션이 생성된다 (FR-2.1, BR-4)
4. 관리자는 등록된 프로모션 목록에서 해당 건을 "게시" 조작하여 상태를 "예정→진행"으로 전환한다 (FR-2.4, BR-4)
5. 필요 시 프로모션 내용을 수정한다 (FR-2.3)
6. 진행 중인 프로모션을 "종료" 조작하여 상태를 "진행→종료"로 전환한다 (FR-2.4, BR-4)

**예외/대안 흐름 - 게임 적용 프로모션**
- 2번에서 게임 적용을 선택하면 경품 목록(이름 등)을 함께 등록한다 (FR-2.2)
- **EX-3 경품 목록 누락**: 경품 목록이 비어 있는 상태로 게시를 시도하면 서버가 게시를 거부한다. 관리자는 경품을 1개 이상 등록한 후 다시 게시한다 (FR-2.2, EX-3)

---

## 시나리오 4. 거래처 담당자 프로모션 조회 및 참여 신청 (게임 미적용)

**액터**: 거래처 담당자

**사전조건**: 로그인 완료, "진행" 또는 "예정" 상태의 프로모션 존재

**기본 흐름**
1. 프로모션 목록에서 진행 중/예정 프로모션을 조회한다 (FR-3.1)
2. 관심 있는 프로모션 상세를 확인한다 (FR-3.1)
3. 참여 신청 버튼을 눌러 신청한다 (FR-3.2)
4. 서버는 (프로모션, 거래처) 조합의 신청 레코드가 없음을 확인하고 신청을 생성한다 (BR-1)
5. 신청 완료 화면을 확인한다

**예외/대안 흐름**
- **EX-1 중복 신청**: 이미 신청한 프로모션에 재신청을 시도하면 서버가 거부하고 기존 신청이 존재함을 안내한다 (FR-3.2, BR-1, EX-1)
- **EX-2 종료/미게시 프로모션 신청**: "종료" 상태이거나 아직 "예정"으로 게시되지 않은 프로모션에 신청을 시도하면 서버가 거부한다 (FR-3.2, BR-3, EX-2)

---

## 시나리오 5. 거래처 담당자 프로모션 참여 신청 (게임 적용, 룰렛 추첨)

**액터**: 거래처 담당자

**사전조건**: 로그인 완료, 게임 적용 프로모션이 "진행" 상태로 게시되어 있음(경품 목록 등록됨)

**기본 흐름**
1. 게임 적용 프로모션 상세에서 참여 신청 버튼을 누른다 (FR-3.2)
2. 서버는 (프로모션, 거래처) 조합의 기존 신청이 없음을 확인하고 신청을 생성함과 동시에 경품 목록 중 하나를 무작위로 즉시 추첨해 결과를 확정한다 (FR-3.2, BR-2)
3. 화면은 룰렛 애니메이션을 재생한 후 확정된 당첨 결과를 표시한다 (FR-3.2)
4. 거래처 담당자는 당첨 결과를 확인한다

**예외/대안 흐름**
- **BR-2 재추첨 불가**: 동일 신청 건에 대해 룰렛을 다시 돌리거나 새로고침해도 서버는 이미 확정된 결과를 그대로 반환하며 재추첨하지 않는다 (BR-2)
- **EX-1 / EX-2**: 시나리오 4와 동일하게 중복 신청, 종료/미게시 신청은 거부된다 (BR-1, BR-3, EX-1, EX-2)

---

## 시나리오 6. 거래처 담당자 신청 취소 및 재신청

**액터**: 거래처 담당자

**사전조건**: 로그인 완료, 참여 신청(상태: 신청) 내역 존재

**기본 흐름**
1. 내 신청 목록에서 취소할 신청 건을 선택한다 (FR-3.4)
2. 취소를 요청한다
3. 서버는 기존 신청 레코드의 상태를 "신청→취소"로 전환한다. 새 레코드를 생성하지 않는다 (FR-3.3, BR-1)
4. 동일 프로모션에 재신청하면 서버는 기존 레코드의 상태를 "취소→신청"으로 전환한다 (새 레코드 생성 없음) (FR-3.3, BR-1)
5. (게임 적용 프로모션인 경우) 재신청은 새로운 신청 행위이므로 서버가 다시 추첨을 수행하고, 이전 당첨 결과를 새 결과로 갱신한다 (FR-3.3, BR-2)

**예외/대안 흐름**
- 재신청 시점에 프로모션이 이미 "종료" 상태라면 신청이 거부된다 (BR-3, EX-2)

---

## 시나리오 7. 관리자 참여 현황 조회

**액터**: 관리자

**사전조건**: 관리자로 로그인 완료, 프로모션 1건 이상 존재

**기본 흐름**
1. 프로모션 목록에서 조회할 프로모션을 선택한다
2. 해당 프로모션의 참여 신청 목록(신청자, 상태, 당첨 결과)을 확인한다 (FR-2.5)

---

## 시나리오 8. 마이페이지 (내 정보 수정, 비밀번호 변경) - 공통

**액터**: 관리자, 거래처 담당자

**사전조건**: 로그인 완료

**기본 흐름**
1. 마이페이지에서 내 정보(이름, 소속 거래처 등)를 조회한다 (FR-4.1)
2. 정보를 수정하고 저장한다 (FR-4.1)
3. 비밀번호 변경 메뉴에서 현재 비밀번호와 새 비밀번호를 입력하고 저장한다 (FR-4.2)

**예외/대안 흐름**
- 비로그인 상태로 마이페이지 접근 시 로그인 페이지로 리다이렉트된다 (EX-4)
