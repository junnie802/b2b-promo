## 배포 중 발견 및 수정한 이슈

### 🔴 (수정완료) 프론트엔드가 자기 자신에게 API 요청을 보내던 문제

최초 배포 시 로그인이 전부 실패했습니다. 원인은 `frontend/src/api/client.js`가 사용하는 빌드 시점 환경변수 `VITE_API_BASE_URL`이 Vercel 프로젝트에 설정되지 않아, axios가 baseURL 없이 프론트 자기 자신(`abc-7782-fe.vercel.app/api/...`)으로 요청을 보내 `405`를 반환했습니다.
- **조치**: Vercel 프론트 프로젝트에 `VITE_API_BASE_URL=https://abc-7782-be.vercel.app` 환경변수 추가 후 재배포 → 정상화 확인
- **조치**: `frontend/vercel.json`에 SPA fallback rewrite(`/(.*) → /index.html`) 추가 → 직접 경로 접근/새로고침 404 해결 확인

## 시나리오 1. 회원가입

- 정상 가입(`buyer.fe.prod@test.com`) → 로그인 페이지 이동, DB에 이름/거래처명 정상 저장 확인 (`s1-01`)
- EX-5(이메일 중복) → "이미 등록된 이메일입니다" 표시 (`s1-02`)

## 시나리오 2. 로그인/로그아웃/EX-4

- buyer 로그인 → `/promotions` 정상 이동 (`s2-01`)
- 로그아웃 후 `/mypage` 직접 접근 → `/login` 리다이렉트 (`s2-02`)
- 관리자 로그인 → `/admin/promotions` 정상 이동

## 시나리오 3·7. 관리자 프로모션 관리/참여현황

- API로 미리 생성한 프로모션 4건(진행 2건, 예정 1건, 종료 1건)이 관리자 목록에 정상 표시 (`s3-01`)
- 룰렛 이벤트 참여현황 조회 → 신청자/거래처/상태/당첨경품/총 신청건수 정상 표시 (`s7-01`)

## 시나리오 4. 거래처 조회/신청 예외

- 예정(id=3)/종료(id=4) 프로모션 상세 → 신청 버튼 비활성화 + 안내문구 (EX-2, `s4-01`, `s4-02`)
- 이미 API로 신청되어 있던 P1에서 재신청 시도 → EX-1 재현: "이미 참여 신청한 프로모션입니다" (`s4-03`)
  - 로컬 환경 테스트(`e2e/report.md`)에서 발견한 것과 동일한 이슈: 상세 페이지가 재진입 시 기존 신청 상태를 재조회하지 않아 신청 완료 상태가 반영되지 않음. 운영 환경에서도 동일하게 재현됨.

## 시나리오 5·6. 신청 목록/취소·재신청/룰렛 재추첨

- 내 신청 목록에서 API로 만든 기존 신청 내역(룰렛 당첨 "텀블러", P1 신청)이 정상 표시 (`s5-01`)
- P1 취소 → "재신청" 링크 노출, P2(룰렛) 취소 후 재신청 → 재추첨되어 결과 화면에 재표시 (BR-2, `s6-01`)

## 시나리오 9. 모바일 반응형

- 375px 뷰포트에서 관리자 프로모션 목록이 가로 스크롤 없이 정상 표시 (`s9-01`)

## 종합 결론

- 배포 중 발견된 심각한 이슈(API baseURL 미설정, SPA 라우팅 404)를 모두 수정하고 재검증하여 정상 동작을 확인했습니다.
- 이 두 이슈를 제외하면, 로컬 개발 환경(`e2e/report.md`)과 API 직접 테스트(`e2e/api-report.md`)에서 확인한 모든 비즈니스 규칙(BR-1~4)과 예외 처리(EX-1~5)가 실제 운영 배포 환경에서도 동일하게 정상 동작합니다.
- 기존에 보고된 "상세 페이지 재진입 시 신청 상태 미반영" UX 이슈는 운영 환경에서도 동일하게 존재하며, 여전히 개선이 필요합니다.
