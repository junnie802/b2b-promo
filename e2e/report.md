## 시나리오 1. 회원가입

- **정상 흐름**: 이메일/비밀번호/이름/소속거래처 입력 → 가입 성공 → 로그인 페이지로 이동
  - `s1-01-signup-form-filled.png`, `s1-02-signup-success-redirect-login.png`
- **EX-5 (이메일 중복)**: 동일 이메일로 재가입 시도 → 400 응답, "이미 등록된 이메일입니다" 필드 오류 표시
  - `s1-03-EX5-duplicate-email.png`

## 시나리오 2. 로그인/로그아웃

- **정상 흐름**: buyer 로그인 → `/promotions`로 이동, 로그아웃 → `/login`으로 이동
  - `s2-01-buyer-login-success-promotion-list.png`
- **EX-4 (비로그인 접근)**: 로그아웃 상태에서 `/mypage` 직접 접근 → `/login`으로 리다이렉트
  - `s2-02-EX4-unauthenticated-redirect-login.png`
- **권한 불일치**: buyer 계정으로 `/admin/promotions` 접근 시 `/promotions`로 차단
  - `s2-03-role-mismatch-admin-route-blocked.png`

## 시나리오 3. 관리자 프로모션 등록~게시

- **정상 흐름**: 등록 시 상태 "예정" 생성 → "게시" 조작으로 "진행" 전환 확인
  - `s3-01-admin-promotion-list.png`, `s3-04-admin-game-promotion-published.png`, `s3-05-admin-promotion-list-full-states.png`
- **EX-3 (경품 없는 게임 프로모션 게시)**: 경품 0건 상태로 게시 시도 → 거부, "경품이 없어 게시할 수 없습니다" 표시. 경품 2개(텀블러/보온병) 추가 후 재시도 → 게시 성공
  - `s3-02-admin-game-promotion-no-prize.png`, `s3-03-EX3-publish-rejected-no-prize.png`

## 시나리오 4. 거래처 프로모션 조회/신청 (게임 미적용)

- **정상 흐름**: 목록(진행/예정 탭)에서 조회 → 상세 확인 → 참여 신청 → "신청 완료" 버튼으로 전환
  - `s4-01-buyer-promotion-list-active.png`, `s4-02-buyer-promotion-list-scheduled.png`, `s4-03-promotion-detail-before-apply.png`, `s4-04-application-success.png`
- **EX-1 (중복 신청)**: 이미 신청한 프로모션에 새로고침 후 재신청 시도 → 서버가 400으로 거부, "이미 참여 신청한 프로모션입니다" 표시
  - `s4-05-EX1-duplicate-application-rejected.png`
- **EX-2 (미게시/종료 신청)**: "예정"(90) 및 "종료"(91) 상태 프로모션 상세에서 참여 신청 버튼이 비활성화되고 "게시 중인 프로모션에만 참여 신청할 수 있습니다" 안내 표시 (서버 요청 전 프론트에서 사전 차단)
  - `s4-06-EX2-scheduled-apply-disabled.png`, `s4-07-EX2-ended-apply-disabled.png`

### ⚠️ 발견된 이슈: 상세 페이지 새로고침 시 기존 신청 상태 미반영

프로모션 상세 페이지(`PromotionDetailPage`)는 신청 성공 시 로컬 상태로만 "신청 완료"를 표시하며, 페이지를 새로고침(재진입)하면 이미 신청한 프로모션인지 서버에 재조회하지 않아 "참여 신청하기" 버튼이 다시 활성화된 것으로 보입니다.

- 서버(BR-1/EX-1)는 정상적으로 중복 신청을 거부하므로 데이터 정합성 문제는 없으나, 사용자 경험상 이미 신청한 사실을 재확인 없이 다시 "신청하기"를 누르게 되어 혼란을 줄 수 있습니다.
- **재현**: 신청 성공(`s4-04`) → 새로고침 → 버튼이 "참여 신청하기"로 원복(`s4-05` 스크린샷 상단 참고) → 클릭 시 서버 400 오류 메시지로만 안내됨
- **제안**: 상세 페이지 로드 시 내 신청 목록(`/applications/me`) 또는 프로모션별 신청 여부 조회를 통해 기존 신청 상태를 반영하면 해결됩니다 (FE-5 완료조건 "신청 성공 시 신청 완료 상태로 화면이 갱신된다"는 최초 진입 기준으로는 충족하나, 재진입 시에는 미충족).

## 시나리오 5. 게임 적용 프로모션 참여 (룰렛 추첨)

- **정상 흐름**: 경품 목록(텀블러/보온병) 노출 → 신청 → 룰렛 모달에서 당첨 결과("텀블러") 표시
  - `s5-01-game-promotion-detail-before-apply.png`, `s5-02-roulette-result-modal.png`
- **BR-2 (재추첨 불가)**: "내 신청 목록"에서 새로고침 후에도 동일 당첨 결과("텀블러") 유지 확인
  - `s5-03-BR2-result-persists-after-reload.png`

## 시나리오 6. 신청 취소/재신청

- **취소**: "내 신청 목록"에서 취소 → 상태 "취소"로 전환, "재신청" 링크 노출 (레코드 삭제 없이 상태만 전환)
  - `s6-01-application-cancelled.png`
- **재신청 (게임 미적용)**: 재신청 후 상태가 다시 "신청"으로 전환됨 (신규 레코드 생성 없음, BR-1)
  - `s6-02-reapplied-status-restored.png`
- **재신청 (게임 적용)**: 룰렛 프로모션 취소 후 재신청 시 새로운 추첨이 수행되어 당첨 결과가 "텀블러" → "보온병"으로 갱신됨 (BR-2)
  - `s6-03-BR2-redraw-on-reapply.png`

## 시나리오 7. 관리자 참여 현황 조회

- **데이터 있음**: 신청자명/소속거래처/상태/당첨경품/신청일 및 총 신청건수 요약이 표시됨
  - `s7-01-admin-applicants-list.png`
- **데이터 없음**: 신청 0건 프로모션에서 "신청 내역이 없습니다" 빈 상태 문구 표시
  - `s7-02-admin-applicants-empty.png`

## 시나리오 8. 마이페이지

- **정보 수정**: 소속 거래처명 수정 후 저장 → "저장되었습니다" 표시 및 값 반영
  - `s8-01-mypage-info-updated.png`
- **비밀번호 변경 - 오류**: 현재 비밀번호를 틀리게 입력 → "현재 비밀번호가 일치하지 않습니다" 표시
  - `s8-02-password-change-wrong-current.png`
- **비밀번호 변경 - 성공**: 올바른 현재 비밀번호로 변경 → "비밀번호가 변경되었습니다" 표시, 새 비밀번호로 재로그인 성공 확인
  - `s8-03-password-change-success.png`

## 종합 결론

- 도메인 정의서의 핵심 비즈니스 규칙(BR-1~4)과 예외 케이스(EX-1~5)는 백엔드에서 모두 정상적으로 강제되고 있음을 확인
- 프론트엔드 예외 처리(EX-2, EX-3, EX-5)는 사용자에게 명확한 한국어 안내 문구로 노출되어 사용자 경험이 양호함
- 발견된 유일한 이슈는 프로모션 상세 페이지가 재진입 시 기존 신청 상태를 재조회하지 않는 것으로, 데이터 정합성에는 영향이 없으나 UX 개선이 필요함 (시나리오 4 참조)
